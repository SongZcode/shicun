## Implemented

- Bilibili videos: platform selector, BV/av/video/ep/ss/PGC links and bounded b23.tv resolution, actual title/cover, quality and part/episode selection. PGC selection updates the actual aid/bvid/cid/episode together, rejects previews and DRM, and reuses existing native AVC/AAC DASH mux, Save/Share, publication and verified reuse. Official H5 login keeps an isolated encrypted session. Paths, parameters, playback states, cookie rules and response mappings remain signed JS/JSON. Long downloads have a separate 8GiB track limit, 30s idle timeout and 2h total-call timeout; Douyin limits remain unchanged.
- Bilibili account works: shared collection page with favorite-folder picker and Recent Likes, immediate cover/title/author/duration pages, retained selections, folder/session/platform caches, opening work options and batch Save/Share. No per-video detail/stream requests while listing. Favorites use native page numbers/has-more; the observed recent-like endpoint returns a bounded 20-item list and ignores paging, so no fictitious history paging is shown. Batches resolve real sparse collection refs to the first part/highest compatible video; individual work options select other parts. Cover loads are bounded to three concurrent requests and retry once independently; a later rebind can retry failed covers. No Bilibili comment or whole-season/all-part batch is added.
- Compatible image sharing: task, collection and stored-file Share offer Original or Compatible Images for WebP/HEIC/AVIF. Native conversion generates temporary opaque JPEG or transparent PNG, retaining dimensions and originals. Animated WebP/decoded animation/image sequences and videos remain unchanged. Conversion creates no extra gallery or verification-index entry; unsupported/oversized images fail explicitly and can still be shared in Original mode. Per-platform logout expires only that platform's configured cookies.

- Work-link resolution, detail/rendition selection, video/image saving, complete AAC soundtrack to M4A, separate platform background music, preview and sharing.
- Phone/code login with encrypted session and matching WebView/request UA.
- Progressive comment lookup, normalized content/commenter/My Comments matching, copied-comment input, replies-first option, cumulative cached re-search and selected-item retention. Comment/reply operations now use a production anonymous native profile with a locally generated identity; signed JS/JSON owns its parameters/UA/origin. Saved WebView login and account requests stay separate. All returned original images and live-photo motion remain selectable. Static sticker source metadata enables compatible JPEG preference without reordering animated/unknown mirrors.
- Comment material UX: text-only matches are hidden from the material list while remaining in scan/cache data. A comment's assets use a compact square grid, independent checkboxes and full-screen image/animation/video preview with previous/next navigation. Preview selection synchronizes with the list; video loops and stops on dismissal. Comment output retries validate and retain successful files, process only pending assets and report counts for the entire selection; partial-result actions say Retry Failed Items.
- Foreground tasks, explicit continuation, page checkpoints/ledger, completed-file verification/reuse, direct gallery/audio publication, task thumbnails, deletion and 20-record cap. Body-read cancellation now closes the active HTTP connection and removes partial files promptly; disconnected-file retry starts cleanly. Comment cache tags include the anonymous identity, account fingerprint and rule version.
- Local JS signing and signed static-bundle verification/rollback. Only the active built-in bundle is packaged.
- Favorite Stickers: separate Douyin collection entry, existing login continuation, real thumbnail grid, animated/static preview, individual/all selection, Save/Share through foreground tasks. Cursor paging, deduplication, stalled/cyclic cursor and page-cap stops, retry with partial results, session isolation and persisted selections are implemented. Collection tasks use account collection keys, with no synthetic work/comment IDs or comment ledger. Live two-item pagination, both media types and system saving/reuse/resave have now been exercised; remaining coverage is listed last.
- Saved/Liked Works: separate tabs, real covers/titles/authors, response-cursor pagination, unavailable-item counts, retained selections, per-session caches and retry. Open a work for existing video/image/audio choices, or batch Save/Share the highest video/all images. Batch tasks retain real work references and per-work manifests, partial retry, pause/continue and verified-file reuse; they do not use comment ledgers. Configured POST/form requests and response decoding on IO support large collection responses. Device restoration uses GridView row selection, fixing a reproduced touch-mode crash in account works and the same call in Favorite Stickers.
